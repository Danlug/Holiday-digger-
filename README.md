# Holiday-digger-
Indie game

## Арт

Персонажи и предметы нарисованы художником; исходный лист лежит в
`art/_source/characters_sheet.jpg`. Нарезка и анимации собираются из него
скриптом:

```
python3 tools/import_art.py art/_source/characters_sheet.jpg
```

Скрипт заливает фон от краёв (серое внутри спрайта — седина, сталь бура —
так уцелеет), усредняет цвет с премультиплированной альфой, чтобы по контуру
не оставалось серой каймы, и квантует палитру. Анимации собираются из одной
стоячей позы: спрайт режется на полосы голова/корпус/ноги, полосы смещаются
покадрово. На 20×40 этого достаточно — читается сам факт шага.

Шесть персонажей: `boy` (герой), `boy_gear`, `grandpa`, `grandpa_gear`,
`grandma_poor`, `grandma_rich`. Кадры героя дублируются в `art/character/`
— там их ищут оба рендерера. Наборы: `idle`, `walk`, `fall`, `fly`, `sleep`
у всех; `dig_shovel` и `dig_pick` у тех, кто копает.

У героя из стоячей позы собирается только `idle` и `sleep`: движение и копка
у него нарисованы покадрово и приходят со своих листов (ниже). Процедурная
сборка осталась деду и бабкам — нарисованных кадров для них нет.

### Движение

Ходьба, свободное падение и оба полёта нарисованы покадрово и лежат листом
`art/_source/move_sheet.jpg`: три ряда по восемь кадров, кадры сгруппированы
по четыре — шесть анимаций. Нарезка:

```
python3 tools/import_move.py art/_source/move_sheet.jpg
```

В игру идут четыре группы: ходьба (`walk`), падение (`fall`), полёт на ранце
с двумя винтами (`fly`, он совпадает с иконкой снаряжения) и полёт на
джетпаке (`fly_jet`). Две оставшиеся — вторые варианты: спокойный цикл шага
и ранец с одним винтом; какая группа чем является, разобрано в шапке
скрипта. Явной группы «стоит спокойно» на листе нет, поэтому `idle` остался
прежним.

Границы кадров взяты по содержимому, а не делением 1024 на 8: кадры стоят
неравномерно, и деление по 128 px разрезало бы фигуры.

По горизонтали кадры сводятся ПО ГОЛОВЕ. Художник ставил фигуру в каждой
клетке по-своему — середина головы гуляет по клетке на 17 px исходника, это
4 игровых пикселя, и в игре это читалось бы как дрожание. По вертикали линия
земли считается один раз на весь лист и переносится в каждую группу от
макушки: в кадрах полёта земли не нарисовано, а под ступнями джетпака ещё и
пламя — низ содержимого там уже не подошва.

### Копка

Анимации копки нарисованы покадрово и лежат отдельным листом
(`art/_source/dig_sheet.jpg`): три ряда по восемь кадров — стальная кирка,
лопата, дедова ржавая кирка. Нарезка:

```
python3 tools/import_dig.py art/_source/dig_sheet.jpg
```

Масштаб и линия земли считаются ОДИН раз на весь лист: опора — рост в
спокойной позе и низ содержимого ряда. Выравнивать каждый кадр по его
собственной рамке нельзя — герой начинает прыгать внутри клетки.

Кадры на листе стоят вплотную, и содержимое иногда переходит через границу
клетки, оставляя у края обрывок чужой кирки. Такие узкие куски, касающиеся
края, выбрасываются; широкие (куча земли, камни) и мелкие крошки внутри
кадра остаются — это порода, которую герой разбивает.

Реквизит с кадров намеренно не убирается: в игре герой копает соседний
тайл, и нарисованный обломок ложится ровно на него.

Процедурная сборка копки из стоячей позы (`anim_dig` в `import_art.py`)
осталась для тех персонажей, у кого нарисованных кадров нет, — для деда.

### Тайлы

Лист пород лежит в `art/_source/tiles_sheet.jpg`, нарезается отдельно:

```
python3 tools/import_tiles.py art/_source/tiles_sheet.jpg
```

Тайлы на листе нарисованы карточками — с тёмной каймой по краю. Для витрины
это красиво, для тайлмапа смертельно: замощённое поле покрывается сеткой
швов. Поэтому кромка обрезается, а остаточное затемнение к краю снимается
выравниванием поля: усреднённый по ВСЕМ тайлам профиль яркости показывает
систематическую часть, её и делим обратно. Считать профиль по одному тайлу
нельзя — выест его собственный рисунок. В конце скрипт печатает оценку шва
по каждому тайлу: 1.0 — шва нет.

Земля — особый случай. Движок разбрасывает четыре варианта по миру
случайно, и четыре РАЗНЫХ грунта с листа дают лоскутное одеяло: они
отличаются по светлоте втрое. Поэтому берём два грунта одной светлоты и
добавляем к каждому поворот на 180° — рисунок меняется, тон нет. Именно
поворот, а не отражение: у пары «тайл и его зеркало» совпадает кромка, и на
стыке возникает симметричная бабочка, которую глаз ловит сразу.

Остальные варианты грунтов с листа в игру не попали — они слишком разные по
тону, чтобы мешаться в одном поле. Их естественное применение — разный
грунт на разной глубине, но это надо решать отдельно.

`tools/gen_art.py` остаётся генератором плейсхолдеров для ненарисованного
(часть UI, окружение) и авторские файлы не перезаписывает — список в
константе `AUTHORED`.
